netcheck-lab · walkthrough

Test the network against what it must do

An intent-driven network test framework. One YAML file says what the network must do. The framework builds the lab from it, tests the live network against it, and explains every failure in terms of the intent that was violated. The same tests run on FRR in Containerlab and on NVIDIA Cumulus Linux.

What it is

From one file to a verdict that names the broken intent.

Intentintent/lab.yaml

Nodes, links, VLANs, OSPF timers, and the promises: which hosts reach each other, which stay isolated.

Buildrender.py · expected.py

Topology and device configs, plus the expected state: VLANs per port, adjacencies per link, routes per router.

Deploybackends/ · labstate.py

Brings the lab up once per session and saves a baseline snapshot right after a real deploy.

Testtests/lab · steps.py

Cases generated from the intent. Every test runs between a snapshot and a restore.

Explainreport.py · artifacts/

Verdict, expected vs actual, the drifted setting, evidence, packet capture, repro command.

It proves the intent

Isolation, reachability, adjacency per link, learned routes, failover with a measured outage, and drift between live state and intent.

Same tests, two backends

Tests talk to capabilities (Ospf, Bridge, Links, Shell), never to a device CLI. The backend decides how to answer.

Every failure explains itself

Reports point at the root cause (sw1:p3 in the wrong VLAN), not at a ping that failed.

One YAML file is the source of truth. The topology, the configs, the test cases and the expected state are all generated from it, so the tests can't drift from the design.

How the tests are tested

      
A network test that passes for the wrong reason is worse than none. These are the checks on the checks.

    

      
164Unit tests, no lab
        
Parsers, expected state, assertions, reports, cleanup and timing, over fake transports and a fake lab. Seconds to run.

        make check · tests/unit

      
16 / 16Real lab tests on a fake lab
        
pytester runs the actual tests/lab files against a healthy fake lab, and against broken ones to prove they fail with the right report.

        test_review_fixes.py

      
10Lab tests on NVUE responses
        
Smoke, OSPF and drift tests pass unchanged when routers and the switch answer in Cumulus NVUE JSON. A contract test checks both parsers give identical OSPF settings for the same intent.

        test_nvue.py · fixtures/nvue/

      
67%Mutation testing
        
mutmut changed the code 5,476 times; 67.2% of the mutants were caught. The opt-in lab profile found two isolation gaps that are now closed: link restores weren't verified, and mutants started from a dirty lab.

        make mutate · make mutate-lab

      
2Demo faults
        
Each one breaks a single intent: h3's port in the wrong VLAN, r2's LAN out of OSPF. The suite must fail and name the cause.

        make fault-wrong-vlan · make fault-missing-ospf

      
2 jobsCI on every push
        
checks: ruff, mypy, unit tests. lab: Containerlab inside the GitHub runner, full lab suite, JUnit check run, reports and pcaps uploaded. SLAs recorded, not enforced, on shared runners.

        .github/workflows/ci.yml

How to read it

        
    
          
  1. Verdict names the intent, in the intent's words.
    2. 
          
  2. Expected and actual as numbers: 0 of 20 replies wanted, 20 got.
    3. 
          
  3. Intent vs live diffs the state the verdict depends on and marks the drift: the root cause.
    4. 
          
  4. Evidence is collected before the verdict, so it shows the lab at the moment of failure.
    5. 
          
  5. Capture proves it on the wire: h1 and h3 now share a broadcast domain.
    6. 
          
  6. Commands run by the test are in logs/<device>.jsonl with raw replies.
    7. 
          
  7. Environment: backend, intent digest, image versions.
    8. 
          
  8. Repro: one command restores the exact snapshot and reruns the test.
    9. 
        

        
The report is designed for the person on call: it says which intent broke, where, and how to reproduce it, without opening the test code.

Status and next

      
What runs today, and what is designed but not built.

    

      

        
PartStateDetail

        
          
Framework coredone
            Intent, expected state, assertions, reports, steps and soft steps, cleanup, timing. Unit-tested.

          
Local backenddone
            Verified on a real lab (Containerlab 0.76, FRR 10.1, Apple Silicon via OrbStack) and in GitHub Actions. Next: pin the switch and host images by digest.

          
NVIDIA, device sidebuilt, offline
            NVUE responses parsed into the same types as FRR; changes through the NVUE revision flow. Tested on JSON samples built from the NVIDIA docs, still to be replaced by responses captured from a real switch.

          
NVIDIA, lab sidespecified
            Requirements and a phased plan: spikes on a real DSX Air simulation, Air API client, topology and NVUE config from the intent, SSH through the oob-mgmt-server, NVUE snapshots, live runs, a measured timing profile, a CI job.

        
      

    

    

      

        
Design decisions (docs/decisions/)

        
    
          
  1. Two backends, one intent
    2. 
          
  2. Composition: transports and capabilities
    3. 
          
  3. Deploy once; snapshot and cleanup registry per test
    4. 
          
  4. Thresholds from protocol timers; SLA vs timeout
    5. 
          
  5. Failure reporting
    6. 
          
  6. pytest, not pyATS; soft steps borrowed from it
    7. 
        

        
New features go requirements → implementation plan → implementation → review → plan check, with Claude Code agents for each stage (.claude/agents/).

      

      

        
Use the backend yourself

        
The object model is the API. In the repo, inside the VM, with the lab up:

        


uv run python
>>> from pathlib import Path
>>> from netcheck.intent import load_intent
>>> from netcheck.backends import get_backend
>>> lab = get_backend("local", load_intent("intent/lab.yaml"), Path("."))
>>> devs = lab.devices()
>>> devs["r1"].ospf.neighbors()
[OspfNeighbor(router_id='2.2.2.2', state='Full', port='p2'),
 OspfNeighbor(router_id='2.2.2.2', state='Full', port='p3')]
>>> devs["sw1"].bridge.vlan_membership()["p3"]
PortVlans(mode='access', vlans=(20,))
>>> devs["r1"].log.summary()   # every command that ran
